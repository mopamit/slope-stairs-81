# מדרגות אל השיפוע — פריזמה

משחק בעברית לחקר ולתרגול שיפוע באמצעות שינוי ב־Y, שינוי ב־X ומדרגות.

## הפעלה

פותחים את `index.html` בדפדפן. אין התקנות, אין תהליך build ואין צורך בשרת או בחיבור ל־Drive. כל הגופנים, האייקונים והצלילים בחבילה.

## העלאה ל־GitHub Pages

1. יוצרים מאגר ב־GitHub.
2. מעלים את **תוכן התיקייה** כך ש־`index.html`, `style.css`, `app.js` ותיקיית `assets` נמצאים בשורש המאגר. אין להעלות רק את ה־ZIP.
3. נכנסים ל־Settings → Pages.
4. ב־Build and deployment בוחרים Deploy from a branch.
5. בוחרים את הענף `main` ואת התיקייה `/(root)`, ולוחצים Save.
6. לאחר השלמת הפרסום פותחים את כתובת האתר שמופיעה במסך Pages.

[הוראות GitHub הרשמיות](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

החבילה מוכנה להעלאה; לא נוצר מאגר ולא פורסם אתר במסגרת הכנת הקוד.

## מה כלול

- מעבדה: גרירת נקודות על סריג של יחידות שלמות או שליטה במקלדת דרך מחוונים; מניעת נקודות חופפות.
- מדרגה גדולה או חלוקה למדרגות קטנות לפי המחלק המשותף הגדול ביותר של השינויים.
- שמונה שלבים בסדר פדגוגי, עם מאגר של 40 תרגילים לכל שלב — 320 בסך הכול. בכל משחק נבחר תרגיל אקראי מתאים לכל שלב.
- במהלך הפעלה רציפה, כל מאגר מתערבב ונשלף ללא חזרה עד מיצויו. אחרי רענון נמנעת חזרה על התרגיל האחרון בכל שלב.
- כפתורי הפתיחה והסיום בעיצוב פריזמה אחיד, באותו גודל ובאותו גובה; בטלפון הם נערמים במרכז.
- באתגרים מזינים רק את השיפוע; אין חובה להזין את השינויים בצירים. אפשר לפתור לפי מדרגות קטנות או לפי השינוי הכולל.
- כתיב מתמטי באמצעות MathML: שבר עם מונה ומכנה במסך הפתיחה, במעבדה, בעזרה ובמשוב.
- עורך שברים עם מונה מעל קו אופקי ומכנה מתחתיו, ומקלדת מתמטית תואמת.
- קבלת מספרים ושברים שקולים, ללא `eval`.
- מספרי הסריג סמוכים לצירים עצמם, ולוח הבקרה מימין במחשב. במסך צר הלוחות נערמים.
- מטבע לכל פתרון, כוכב לפתרון בניסיון הראשון ורצף של פתרונות בניסיון הראשון.
- שלושה ניסיונות עד רמז נוסף; אין פסילה ואין הגבלת זמן. הלבבות מתחדשים לאחר הרמז.
- זמן פעיל ומד דקה אופציונלי ללא השפעה על התוצאה.
- מסך פתיחה, הוראות, תפריט, מפת משימות, סיום והתחלה מחדש.
- צלילים מקוריים להצלחה, שגיאה וסיום, עם השתקה שנשמרת במכשיר.
- תצוגה מותאמת לטלפון, RTL, בידוד ביטויים מתמטיים, מקלדת מתמטית ומיקוד נגיש.

התקדמות במשחק נשמרת רק בזמן שהעמוד פתוח. מעבר לבית, לתפריט או למעבדה אינו מוחק תשובות; רענון העמוד מתחיל משחק חדש. הגדרת ההשתקה ומזהי התרגילים האחרונים נשמרים מקומית כדי למנוע חזרה מיידית לאחר רענון. אין איסוף נתונים או שליחת תוצאות.

## קבצים

- `index.html`: מסכי המשחק.
- `style.css`: עיצוב פריזמה והתאמה למסכים.
- `app.js`: הגרף, עורך השברים ומנגנון המשחק.
- `questions.js`: מאגרים לפי שלב ומנגנון הגרלה ללא חזרות.
- `assets/`: נכסים מקוריים; `manifest.json` מתעד את מקורם.
- `PRISMA.md`: מיפוי הנכסים לעקרונות ולמסכים.
- `tests/smoke.cjs`: בדיקת דפדפן של מסלול המשחק והתצוגה.

## התאמת שאלות

עורכים את הגדרות `stages` ב־`questions.js`. לכל שלב יש מזהה, כותרת ותנאי מתמטי. המאגרים נוצרים מקואורדינטות שלמות בטווח ‎-4 עד 4, עם 40 תרגילים נפרדים לכל שלב. התרגילים עוברים בדיקת התאמה לשלב; שתי הנקודות תמיד שונות. קבוצות שיפוע משולבות כדי לגוון גם את השיפוע וגם את מיקום הנקודות.

אפשר לבדוק את המאגרים ללא התקנות:

```sh
node tests/question-bank.cjs
```

## בדיקות

נבדקו כל 320 התרגילים מול תנאי השלב, 40 הגרלות ללא חזרה וחידוש המאגרים. נבדקו גם מידות ויישור כפתורי הסיום. ב־Chrome נבדקו: כתיב שברים, קלט מונה ומכנה, מענה בשיפוע בלבד, מיקום מספרי הצירים ולוח הבקרה, רצף של שמונה פתרונות, תשובה שגויה, שברים, ישר אנכי ואופקי, מסך סיום, מחווני המעבדה, עזרה, טעינת נכסים ותצוגות 320px ו־360px. נבדקה גם תצוגה חזותית במחשב ובטלפון.

להרצת בדיקת הדפדפן בסביבת פיתוח עם Node.js:

```sh
npm install --no-save playwright
npx playwright install chromium
node tests/smoke.cjs
```

אפשר להגדיר `CHROME_PATH` לנתיב Chrome מותקן. אין צורך בתלויות אלה להפעלת המשחק.
